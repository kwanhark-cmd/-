# 판매·배포 단계에서 할 일

첫 버전은 의뢰자 한 사람이 쓰는 것을 기준으로 만들었고, 여러 사용자 구조(사용자별 로그인·자료 분리)는 처음부터 넣어 두었습니다. 다른 사람에게 판매·배포하려면 아래가 필요합니다.

## 1. 구글 관련
- [ ] **OAuth 앱 심사 (구글 인증)**: 유튜브 `youtube.force-ssl`, 블로그 `blogger` 권한은 "민감한 범위" 라 구글 심사가 필요. 심사 전에는 테스트 사용자 100명까지, 연결이 7일마다 만료됨.
  - 준비물: 앱 홈페이지, 개인정보 처리방침 주소, 이용약관 주소, 앱 사용 영상(권한을 어디에 쓰는지 보여 주는 영상), 승인된 도메인
- [ ] **YouTube API 서비스 감사(Audit) + 할당량 증가**: 여러 사용자가 쓰면 하루 10,000 으로 부족. 구글 "YouTube API Services - Audit and Quota Extension Form" 제출.
- [ ] YouTube API 서비스 약관·개발자 정책 준수 확인 (자료 보관 기간, 사용자 동의 표시 등)
- [ ] 판매용 OAuth 클라이언트는 개발자 회사 명의로 만들고, 앱에 기본값으로 넣을지(사용자가 따로 만들 필요 없게) 결정

## 2. 법률·문서
- [ ] **개인정보 처리방침**: 수집 항목(계정 토큰, 채널·영상 정보, 음성 메모), 보관 위치(사용자 기기 안), 외부 전송(구글·Anthropic·힉스필드·피그마), 보관 기간, 삭제 방법(설정 → 초기화)
- [ ] **이용약관**: AI 생성 콘텐츠 책임, 플랫폼 정책 위반 책임, 환불 규정
- [ ] AI 콘텐츠 표시 의무 안내 (유튜브·국내 법규)
- [ ] 저작권 안내 (사용자 소재 책임, 앱의 저작권 확인 기능 설명)
- [ ] 글꼴 라이선스 표시: Noto Sans KR (SIL OFL, `app/assets/fonts/NotoSansKR-OFL.txt`)
- [ ] 사용한 오픈소스 패키지 라이선스 화면 (Flutter `showLicensePage` 추가)

## 3. 서버 운영 (필요할 때)
지금은 서버 없이 모든 자료가 사용자 기기 안에 있음. 아래 기능을 원하면 서버가 필요:
- [ ] 컴퓨터 ↔ 휴대폰 자료 자동 동기화 (지금은 백업 파일로 옮김)
- [ ] 휴대폰에서 승인 → 컴퓨터 작업 실행기에 바로 전달
- [ ] 판매 라이선스·결제·사용자 계정(온라인 로그인)
- [ ] AI 비용을 회사가 대신 내고 사용자에게 청구하는 방식 (지금은 사용자가 자기 키 사용)
- [ ] 문제 신고를 서버로 바로 보내기 (지금은 파일로 내보냄)
- 고려: 서버를 두면 토큰을 서버에 보관할지(보안 부담 큼), 기기에만 둘지 결정 필요

## 4. 앱 서명·배포
- [ ] **안드로이드**: 정식 서명 키 만들기(지금은 테스트 서명), 구글 플레이 개발자 계정(25달러), 앱 이름·아이콘·스크린샷·개인정보 처리방침 등록, 대상 SDK 최신 유지
- [ ] **맥**: 애플 개발자 계정(연 99달러), 코드 서명 + 공증(notarization). 서명 후 보안 저장소를 데이터 보호 키체인으로 바꿀 수 있음 (DECISIONS 14번)
- [ ] **윈도우**: 코드 서명 인증서(경고 창 줄이기), 설치 프로그램(MSIX 또는 Inno Setup)
- [ ] **아이폰**: 구조만 열어 둠. 애플 개발자 계정, 백그라운드 실행 제약 검토 후 개발
- [ ] 자동 업데이트 방법 (스토어 또는 업데이트 확인 기능)
- [ ] 앱이 완전히 꺼져 있어도 정한 시간에 자동 작업을 하려면: 윈도우 작업 스케줄러 / 맥 launchd 등록 기능 (DECISIONS 37번)
