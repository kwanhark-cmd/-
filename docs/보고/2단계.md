# 2단계 보고 — 콘텐츠 제작과 업로드

## 만든 것
- **"제작" 메뉴**: 채널·형식(쇼츠 / 롱폼 / 다큐멘터리 / 사진·이미지 게시물 / 음성 대화형)·주제·음성 메모를 고르면 채널 스타일 카드에 맞춰 제목·설명·키워드·썸네일 문구·대본을 함께 만듦. 내용은 직접 고칠 수 있고 항목마다 복사 버튼.
- **영상 파일**: "내가 만든 영상 넣기"(파일 고르기), "힉스필드로 영상 만들기"(예상 크레딧과 남은 크레딧을 보여 주고 사용자가 승인해야만 실행). 구글 비즈·브루는 "준비 중".
- **업로드는 항상 비공개**: 올리기 전에 화면과 음성으로 확인 + AI 콘텐츠 표시 방법 선택(설명 글 / 채널 소개 / 업로드 설정의 AI 항목). 올린 뒤 "확인 대기 목록"에 들어가고, "유튜브에서 확인하기"로 스튜디오를 열어 사용자가 직접 공개. 공개 후 "확인하고 공개했어요"를 누르면 목록에서 빠짐.
- **한도 부족 시**: 업로드하지 않고 "내일 올리기 준비됨"으로 표시 → 다음 날 브리핑에서 알려 주고, 사용자가 다시 "올리기"를 눌러야 올라감 (자동 업로드 없음).
- **반복 방지**: 같은 채널 최근 30일 콘텐츠와 너무 비슷하면 만들지 않음. **하루 제작 한도**(기본 3개, 설정에서 변경).
- **도구 연결 화면**(설정 → 콘텐츠 제작 → 제작 도구 연결): 도구마다 초록(연결됨)/빨강(안 됨·만료)/회색(준비 중), 연결 테스트, 연결 해제, 만료 시 "다시 연결". 힉스필드는 API 키, 피그마는 OAuth. 사용 우선순위 변경. 앱 금고 연동은 틀만.
- **음성**: "요리 채널에 쇼츠 하나 만들어", "비공개 영상 목록 읽어줘" 가 실제로 동작. 아침 브리핑에 확인 대기 수·미룬 업로드·남은 제작 수 추가.

## 테스트한 방법과 결과
- 새 테스트 13개 + 화면 흐름 1개 추가 → **전체 85개 통과**
  - 5가지 형식 모두 생성, 하루 한도, 반복 방지, 음성 메모 소재, 음성으로 제작
  - 확인 없이 업로드 안 함, 영상 없으면 안내, 비공개 업로드 → 확인 대기 → 확인 완료 (앱은 공개 전환하지 않음)
  - 한도 부족 → 내일 올리기, 다음 날 자동 작업이 업로드하지 않음
  - 힉스필드: 승인 없이는 크레딧 사용 안 함, 크레딧 부족 시 중단
  - 도구 상태 표시, 키는 보안 저장소에만
  - 화면 흐름: 제작 → 영상 넣기 → 업로드 확인(음성 안내 포함) → 확인 대기 목록
- 정적 검사 0개, 형식 검사 통과, 리눅스 빌드 성공
- 1단계 커밋의 GitHub Actions: 테스트·리눅스·윈도우·맥·안드로이드 **모두 성공**
